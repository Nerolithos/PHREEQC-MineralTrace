# v0.6.0：约束驱动的候选机制筛选

本工作流从声明的环境范围自动枚举过程组合，使用真实 PHREEQC 检查反应，再比较用户证据。用户不需编排矿物激活顺序，也不需要给事件手动绑定反应步骤。它是有限的条件机制筛选，不是连续反演或地质年代重建。

## 运行

在仓库根目录设置 PHREEQC 路径后：

```sh
julia --project=. scripts/discover.jl examples/discovery.toml results
```

环境变量、引擎安装见 [README](../README.md)。打开终端打印的 report.html；报告内嵌实际计算图，逐候选展开。所有示例流体、事件来源、搜索边界均为 SYNTHETIC / SIMULATED，不代表真实矿物标本。初始 pH 是状态输入，后续 pH 由真实反应计算，绝不按预设序列覆盖。

## 配置与自动生成规则

复制 [完整配置](../examples/discovery.toml)。顶层流体、固相、诊断与事件字段沿用 [v0.5 参考](REFERENCE.md#v050reactive-mineral-path-explorer)；**不接收 paths、bindings、active_phases 或相激活策略**。

必须声明 `accessibility = "all_declared_phases_always_accessible"`。每个监测矿物都有初始库存、反应方向、目标 SI 和来源。它们在所有候选、共同初始平衡和每一步环境操作中完全相同。初始 SOLUTION 物种分布只用于建立初始库存；随后立刻进行共同的全相平衡，不是人为控制成矿顺序的隔离阶段。

`[search]` 必填字段：

| 字段 | 含义 |
| --- | --- |
| `allowed_processes` | 在 equilibrium、cooling、HCl、NaOH 中显式选择，不自动补入其他机制 |
| `max_depth` | 1–4 个环境操作，不含共同初始平衡；不是持续时间 |
| `max_candidates` | 全部网格合计的不同化学候选预算，1–2000；超限在调用引擎前拒绝，绝不只保留最优子集 |
| `max_total_addition_mol` | 全路径 HCl + NaOH 增量之和上限，最多 0.04 mol |
| `reaction_threshold_mol` | 每步固相增／减检测阈值，必须高于绝对数值记账容差 |
| `source_id` | 对搜索假设与规则的来源说明，合成教学来源不能用于真实标本 |

所有路径均先进行共同初始平衡。`equilibrium` 允许保留“只做初始平衡”的对照；重复无变化等待不构成新路径。冷却仅生成严格降温的离散目标值；不加热。药剂单次增量 >0、<=0.01 mol，执行中性化学式无载体水添加，累积量服从预算。酸加碱可能增加盐库存，所以这种组合不会被当成“什么也没发生”而删除。

深度不超过上限的每条非空合法操作序列均保留，包含单纯冷却、分阶段冷却、酸化、碱化及其混合。生成不读取事件方向，不按观测筛选候选；事件或证据反向不会改变生成的环境操作和化学身份。整个候选清单写入 generated-candidates.toml 后才开始计算。

### 参数范围与离散化

必须明确提供三个 `[[grids]]`：

- `role = "baseline"`：初始参数范围和环境操作采样。
- `role = "resolution"`：在相同上下界增加采样，必须包含基线样点且实际增加分辨率。
- `role = "range"`：环境操作采样保持与基线相同，改变至少一个初始参数的范围。

每个网格都含 `id`、`source_id`、递增唯一的 `temperature_values_c`、`titrant_amounts_mol` 和 `[grids.initial_values]`。初始参数支持 pH、temperature 或 Ca/F/C(4)/Na/Cl，各轴显式提供有限样点；总浓度为 mol/kgw。每轴最多 20 个样点，笛卡尔积受总预算限制。只在一个参数上变化时，其余组成保持声明值，不自动电荷修正。

初始范围是额外的假说。即使名义初始配方来自 Observation，生成的采样情景仍标为 Assumption，并保留原始来源和原始输入；不会把推演浓度冒充测量。当前范围检查针对初始参数；不提供未采样连续域的结论。已知固定流体也应将敏感性情景与真实测量区分，不能虚构误差条来定义范围。

相同化学路径跨网格只计算一次，身份包括完整初始配方、固相库存／方向／目标 SI、边界及环境序列。它不包含事件先后方向。解析清单与每个真实输入、数据库、源码和完整状态交接均有 SHA-256；不存在近似缓存匹配。

## 三类结果的严格语义

自动事件代理规则公开固定：单个矿物阶段在初始平衡之后首次达到逐步固相增／减阈值时，获得一个**平衡增量代理位置**。形成和溶解分别识别；不从 SI > 0 自动生成形成事件。规则本身是筛选假设，不是独立观测。

| 筛选结果 | 模型层面的含义 |
| --- | --- |
| compatible | 所需模型反应发生、不同操作的代理顺序符合声明边、来源与诊断满足策略；条件相容 |
| incompatible | 硬守恒／方向边界失败，或在有限路径中缺少所需模型反应／代理顺序反转；仅排除该模型筛选条件 |
| undetermined | 初始平衡已有反应、同一批反应、重复矿物阶段、来源缺失、阈值需审查、严格模式适用性未验证或计算失败 |

**所有候选的 `formation_order_classification` 始终是 undetermined。** 热力学平衡不能预测成核滞后、结晶速率或真实时间顺序；即便两个阶段在不同操作首次显著增量，也不能认证它们对应天然观察到的阶段。代理不相容同样不能直接推翻实测地质关系。不得把顶层条件筛选标签读成“真实历史成立／不存在”。

同一步内部顺序未知。初始平衡沉淀属于初始条件未知前史，不能借它赋予早期成矿事件。一个矿物有重复事件时，不自动猜哪次增量对应哪一阶段。未建模矿物、缺失来源不被补齐。用户证据 DAG 保持原样，循环仍明确失败。

`strict` 模式保留未验证模型的适用性未知；exploratory 的 compatible 仍为条件相容。电荷阈值违反需审查，不意味着物理不可能；总净电荷残差与原子库存守恒则单独核对。失败候选保留已计算状态、原始归档与错误，未算出的值不会填零。

## 多解与敏感性输出

保留全部候选，包括全部条件相容项。按“是否有显著沉淀／溶解、是否在初始平衡发生、相对代理顺序”形成**定性反应组**。同组仅意味着这些指标相同；不是 pH、库存或路径的数值相等，也不是同一个历史。实际轨迹与逐步数据始终可查。

敏感性报告列出每个网格的分类数量、共同／增加／移除的化学候选和定性组的新增／丢失。数量不是概率或证据权重。细化未出现新组也不证明收敛；仍可能遗漏网格之间、范围之外、更深路径或其他模型下的机制。反应阈值与数据库本轮不自动变化，这些局限要与网格敏感性分开。

## 导出、复现与 API

导出独立 HTML／SVG、candidates.csv、steps.csv、balances.csv、sensitivity.json、response-groups.json、analysis.json、results.json、全部显式生成输入、原始 PHREEQC 文件、状态快照、源码／数据库／文献登记快照和 reproduce.jl。

```julia
using MineralTrace
s = load_discovery("examples/discovery.toml")
generated = generate_candidates(s)  # 无需 PHREEQC；只检查规则和预算
r = discover_paths(s, PHREEQCConfig(); root="results")
report(r)
```

在导出文件夹内使用同版本引擎：

```sh
PHREEQC_EXECUTABLE=/absolute/path/to/phreeqc julia --project=. reproduce.jl
```

`analysis.json` 去除运行目录等非科学字段，用于比较确定性结果；results.json 另保留可审计的原始目录。完整归档复现不依赖开发者 /tmp 数据库，但引擎可执行文件仍需提供。
